# youtube_analyzer

Сервис анализа видео YouTube-канала для личного использования. Пользователь вводит
адрес канала, получает таблицу его Video и Shorts с метриками и выгружает её в Excel.

Источник требований — `tz.txt` в корне. Репозиторий — `lpcms/youtube_analyzer` (приватный),
работа ведётся через GitHub issues.

## Стек

- **Next.js 16** (Turbopack), App Router, серверные действия. React 19, TypeScript 5.9
  в strict-режиме плюс `noUncheckedIndexedAccess`.
- **Prisma 7 + SQLite** (`better-sqlite3`) — история выгрузок и источник строк
  для таблицы. Конфиг — `prisma7.config.ts`, клиент генерируется в
  `src/generated/prisma` и в репозиторий не коммитится: его создаёт `postinstall`.
- **YouTube Data API v3** — единственный источник данных.
- **Tailwind CSS 4** — оформление. **TanStack Table** — сортировка и пагинация.
- **Vitest 4** + React Testing Library + MSW — модульные и интеграционные тесты.
  **Playwright** — E2E.
- **ESLint** + Prettier.

## Конвенции

**Счётчики различают ноль и отсутствие.** У видео с отключёнными лайками или
комментариями API возвращает поле отсутствующим — это `null`, а не `0`. В таблице
выводится «н/д». Формула вирусности обязана такой случай пережить.

**Длительность хранится в секундах** целым числом. API отдаёт ISO 8601 (`PT1M30S`);
разбор и форматирование — отдельные функции со своими тестами.

**Даты хранятся в UTC**, в таблице выводятся как `2026-09-21 14:21`. Собственного
форматирования через `toLocaleString` не использовать — формат из ТЗ фиксирован.

**Ключ API живёт только на сервере.** Переменная `YOUTUBE_API_KEY` без префикса
`NEXT_PUBLIC_`. Обращения к YouTube — только из серверного кода.

**Описание видео выводится как текст**, никогда как HTML: в описаниях бывает
произвольная разметка и ссылки.

**Вся валидация входа — через zod**, на сервере, а не только в форме.

## Дизлайки

Столбца дизлайков в проекте нет. YouTube убрал публичные дизлайки в декабре 2021,
API их не отдаёт, а сторонние сервисы дают оценку, а не факт. Это сознательное
отступление от п.3 ТЗ, зафиксированное в PRD. Формула вирусности построена
на просмотрах, лайках и комментариях.

## История каналов

**Источник правды — SQLite, и только он.** Каналы сопоставляются по `channelId`
(`UC…`): он неизменен, в отличие от названия и `@handle`. Список ранее выгруженных
каналов, их таблицы, сортировка и пагинация читаются из БД.

**Метрики — ряд наблюдений, а не текущее значение.** Неизменное у видео (тип,
длительность, дата публикации, описание) лежит в `Video`; изменчивое (просмотры,
лайки, комментарии, вирусность) — в `VideoStat`, по строке на каждую выгрузку.
Каждая выгрузка заводит `FetchRun` и свой набор `VideoStat`, прежние не затираются:
на этом стоит сравнение двух дат. Таблица по умолчанию показывает последний снимок.
Число снимков не ограничивается, чистка — только по удалению канала из истории.

**`history/` — архив снимков, а не хранилище.** После успешной выгрузки туда
кладётся `.xlsx`, тот же, что отдаёт «Скачать таблицу». Это побочный продукт:
сервис обязан работать при удалённой папке. Читать данные из этих файлов нельзя —
если появится такой соблазн, значит, нужного поля не хватает в схеме БД.

Прерванная выгрузка снимка не оставляет: в файле лежал бы обрывок канала,
на диске неотличимый от полного среза. Скачать такую таблицу кнопкой всё ещё
можно — но осознанно, а не найдя её потом в архиве.

**Имя снимка — название канала, его `channelId` и время выгрузки до секунды.**
Идентификатор потому, что название неуникально и меняется; время потому, что
выгрузок бывает несколько в день, а затирать прежний снимок нельзя. Запись идёт
с флагом `wx`: совпавшее имя разводится суффиксом, а не перезаписью. Папка
задаётся `HISTORY_DIR` — это нужно прогонам, чтобы тесты не писали в настоящий
архив и не сносили его.

**«Начать» всегда идёт в YouTube** и обновляет канал: метрики пишутся новым
снимком, новые видео добавляются, исчезнувшие помечаются, вторая запись канала
не создаётся.
Чтение без обращения к API — это открытие канала из истории. Отдельной кнопки
«Обновить» нет, устаревание кэша по времени не вводится.

**Исчезнувшим видео считается только то, которого не оказалось при полном
обходе.** Выгрузка с ограничением по количеству останавливается на полпути,
выгрузка одного типа не смотрит на второй, прерванная не дошла до конца —
после них невстреченное видео просто не запрашивали. Пометить его исчезнувшим
значило бы соврать, поэтому `goneAt` ставится только после успешного обхода
канала целиком и обоих типов. Дата ставится один раз: нужна та, когда видео
пропало, а не та, когда его в последний раз не нашли.

## Отказы API

**Отказ YouTube — не пятисотка.** Исчерпанная квота, непринятый ключ и молчащая
сеть возвращаются как обычный ответ с понятным сообщением. Собранное до отказа
остаётся: выгрузка становится PARTIAL, а не FAILED.

**Тексты отказов — в `src/lib/failure-message.ts`**, один список на форму
и на строку «Причина остановки». Код отказа (`quota-exceeded`) на экран
не попадает: пользователю он ничего не говорит.

**Ключ не попадает в текст ошибки.** `YouTubeApiError` чистит сообщение
в конструкторе: низовая ошибка сети вполне может притащить с собой адрес
запроса, а ключ живёт в строке запроса.

**Повторяется только то, что может пройти со второго раза** — молчащая сеть
и пятисотка Google. Квоту и непринятый ключ повторять бессмысленно. Попыток
три, с растущей паузой; дальше выгрузка заканчивается частичным результатом.

**Состояние сервиса считается без обращения к API.** Ключ — переменная
окружения, последняя выгрузка — строка в базе, расход квоты — счётчик процесса.
Проверять связь «пингом» значило бы тратить квоту на каждое открытие страницы.

## Живые данные на странице

**Страница отдаёт первый снимок, дальше его обновляет форма точечно.**
Состояние сервиса и список каналов приходят с сервера при открытии; после
выгрузки и после удаления список перечитывается отдельным действием.

**`router.refresh()` для этого не годится** — проверено на практике.
Он пересобирает весь сегмент, открытая таблица перемонтируется, и сортировка
с размером страницы сбрасываются на умолчания прямо под руками пользователя.
В прогонах E2E это же давало и плавающие падения с «execution context was
destroyed». Точечное серверное действие меняет ровно то, что должно.

## Квота API

10 000 единиц в сутки. `search.list` стоит 100 единиц за вызов и потому не
используется для перебора видео: список берётся через `playlistItems.list`
(1 единица за 50 видео) из плейлиста загрузок канала, метрики — через
`videos.list` (1 единица за 50 видео). Исчерпанная квота — штатная ситуация,
у неё должно быть понятное сообщение в интерфейсе, а не пятисотка.
