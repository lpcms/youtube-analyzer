# PRD: Анализатор видео YouTube-канала

**Дата**: 2026-09-21
**Статус**: Draft
**Источник**: `tz.txt`, разбор — `docs/tz-analysis.md`

## Цель

Дать владельцу канала одну страницу, на которой по адресу канала собирается таблица
его Video и Shorts с метриками и оценкой вирусности, чтобы находить удачные видео
без ручного обхода YouTube Studio. Таблицу можно отсортировать, пролистать
и выгрузить в Excel.

## Пользовательские сценарии

- Пользователь вставляет адрес канала, оставляет обе галочки и «все видео», жмёт
  «Начать» → видит прогресс выгрузки, затем таблицу со всеми Video и Shorts канала.
- Пользователь вводит 50 и снимает галочку Video → получает таблицу ровно из
  50 последних Shorts.
- Пользователь вводит адрес не с youtube.com → видит текст ошибки под полем,
  кнопка «Начать» не запускает выгрузку.
- Пользователь снимает обе галочки → «Начать» недоступна с пояснением, что нужно
  выбрать хотя бы один тип.
- Пользователь кликает заголовок «Просмотры» → таблица сортируется по убыванию,
  повторный клик — по возрастанию.
- Пользователь кликает URL в строке → видео открывается в новой вкладке.
- Пользователь жмёт «Скачать таблицу» → получает `.xlsx` со всеми строками выгрузки,
  а не только с текущей страницей.
- Пользователь открывает сервис и видит список ранее проанализированных каналов →
  выбирает один → сразу получает его таблицу, без обращения к YouTube.
- Пользователь вводит адрес канала, который уже есть в истории, и жмёт «Начать» →
  данные канала обновляются, вторая запись в истории не появляется.
- Пользователь удаляет канал из истории → запись, её видео и снимок исчезают.
- Квота API исчерпана на середине выгрузки → пользователь видит, сколько успели
  собрать, и понятную причину остановки, а не ошибку сервера.

## В скоупе

**Форма запроса**
- Поле адреса канала. Поддерживаются `/@handle`, `/channel/UC…`, `/c/Name`,
  `/user/Name`, в том числе с хвостами `/videos`, `/shorts`, `/featured`.
- Количество видео: положительное целое либо признак «все».
- Галочка Video, по умолчанию включена.
- Галочка Shorts, по умолчанию включена.
- Кнопка «Начать».

**Выгрузка**
- Данные берутся из YouTube Data API v3 через `channels.list` → `playlistItems.list`
  → `videos.list`.
- Заданное количество считается по строкам выбранных типов.
- Выгрузка идёт заданием с наблюдаемым прогрессом.
- Результат сохраняется в SQLite и служит кэшем при повторном запросе.

**Таблица**
Колонки: URL (кликабельный, открывается в новой вкладке), Тип, Длительность,
Просмотры, Лайки, Комментарии, Вирусность, Дата (`2026-09-21 14:21`), Описание.
Сортировка по любой колонке кроме URL и Описания. Пагинация на стороне БД.

**Вирусность**
```
ER         = (лайки + 2 × комментарии) / просмотры
Вирусность = round(10 × (0,6 × ER / ER_медиана + 0,4 × просмотры / просмотры_медиана), 1)
```
Медианы считаются по всей выгрузке, отдельно для Video и для Shorts. 10,0 — типичное
видео своего типа. Верхняя граница 100.

**Экспорт**
- Кнопка «Скачать таблицу» отдаёт `.xlsx` со всеми строками выгрузки в текущем
  порядке сортировки.

**История каналов**
- Список ранее выгруженных каналов на главной: название, число Video и Shorts,
  дата последней выгрузки.
- Выбор канала из списка показывает его таблицу из SQLite, без обращения к API.
- «Начать» по каналу, который уже в истории, обновляет его данные и отметку
  времени, не создавая второй записи.
- Удаление записи из истории вместе с её видео и снимком.
- Архив снимков: каждая успешная выгрузка дополнительно сохраняется в `history/`
  файлом `.xlsx`. Снимок — побочный продукт, а не хранилище: сервис читает данные
  только из SQLite и работает, даже если папку `history/` удалить.

**Документация**
- `README.md` пишется в конце проекта, когда состав возможностей и команд
  окончательно устоялся: назначение сервиса, установка, получение ключа YouTube API,
  команды запуска, описание колонок и формулы вирусности.

## Не в скоупе

- Авторизация и учётные записи — сервис личный (п.1 ТЗ).
- **Столбец «ДизЛайки»** — см. «Отступления от ТЗ».
- Сравнение нескольких каналов между собой.
- Графики и визуализация динамики.
- История метрик во времени: хранится последний снимок, а не ряд наблюдений.
- Анализ комментариев, тегов, обложек, транскриптов.
- Развёртывание и публичный доступ — запуск локальный.

## Отступления от ТЗ

**Столбец «ДизЛайки» (п.3 ТЗ) не реализуется.** YouTube убрал публичные дизлайки
в декабре 2021: их не отдаёт ни API, ни страница видео, а сторонние сервисы дают
экстраполяцию по выборке, то есть оценку вместо факта. Дизлайки исключены из
таблицы и из формулы вирусности. Решение согласовано 2026-09-21. На этапе 9
регламента (UAT) расхождением не считается.

## Технические ограничения

- **Квота YouTube API** — 10 000 единиц в сутки. `search.list` (100 единиц)
  не применяется для перебора видео; допустим только как фоллбэк для адресов
  вида `/c/Name`.
- **Тип видео API не сообщает.** Shorts определяется длительностью ≤ 180 секунд
  с подтверждением через `youtube.com/shorts/<id>`. Эвристика опирается на
  неофициальное поведение — главный риск проекта.
- **Скрытая статистика.** Отключённые лайки или комментарии приходят как отсутствие
  поля. Это `null`, не ноль: в таблице «н/д», в медиану не входит, вирусность «н/д».
  При нулевых просмотрах вирусность тоже «н/д».
- **Ключ API только на сервере**, переменная `YOUTUBE_API_KEY` без `NEXT_PUBLIC_`.
- **Вирусность зависит от всей выгрузки**, поэтому считается один раз по её
  завершении, а не при отрисовке страницы таблицы.
- **Описание выводится как текст**, никогда как HTML.
- Стек зафиксирован `CLAUDE.md`: Next.js 15 App Router, React 19, TypeScript strict,
  Prisma + SQLite, ESLint.

## Критерии готовности

- [ ] Адрес канала в формах `/@handle`, `/channel/UC…`, `/c/Name`, `/user/Name`,
      в том числе с хвостом `/videos` или `/shorts`, приводится к идентификатору канала.
- [ ] Адрес не с домена youtube.com отклоняется с сообщением под полем, выгрузка
      не запускается.
- [ ] Несуществующий канал даёт сообщение «канал не найден», а не пустую таблицу.
- [ ] Поле количества принимает положительное целое и признак «все»; ноль,
      отрицательное и текст отклоняются.
- [ ] При снятых обеих галочках кнопка «Начать» недоступна и указана причина.
- [ ] Обе галочки включены при первой загрузке страницы.
- [ ] Заданное количество N даёт ровно N строк выбранных типов, если на канале
      их хватает, и все имеющиеся, если нет.
- [ ] Выбор «все видео» выгружает канал целиком, включая каналы более 50 видео
      (то есть постраничный обход работает).
- [ ] Снятая галочка Video оставляет в таблице только строки с типом Shorts,
      снятая Shorts — только Video.
- [ ] Видео длительностью ≤ 180 секунд, подтверждённое как Short, получает тип
      Shorts; обычное короткое видео остаётся Video.
- [ ] В таблице присутствуют все девять колонок из раздела «В скоупе».
- [ ] URL открывает видео в новой вкладке.
- [ ] Длительность выводится как `1:30` для 90 секунд и `1:02:03` для 3723 секунд.
- [ ] Дата выводится в формате `2026-09-21 14:21`.
- [ ] Видео с отключёнными лайками показывает «н/д» в колонке Лайки и в колонке
      Вирусность, и не влияет на медиану.
- [ ] Вирусность медианного видео своего типа равна 10,0 ± 0,1.
- [ ] Вирусность считается отдельно по Video и отдельно по Shorts.
- [ ] Клик по заголовку сортируемой колонки меняет порядок строк, повторный клик
      меняет направление, направление видно в заголовке.
- [ ] Сортировка применяется ко всей выгрузке, а не к текущей странице.
- [ ] Пагинация показывает номер страницы и общее число строк, переключение страниц
      не теряет сортировку.
- [ ] Кнопка «Скачать таблицу» отдаёт `.xlsx`, который открывается в Excel.
- [ ] В файле `.xlsx` столько строк данных, сколько в выгрузке, и те же колонки,
      что в таблице.
- [ ] Во время выгрузки виден прогресс, кнопка «Начать» заблокирована от повторного
      нажатия.
- [ ] Повторное нажатие «Начать» по уже выгруженному каналу обновляет его данные
      и отметку времени, не создавая второй записи и не плодя дублей видео.
- [ ] Исчерпанная квота даёт сообщение с причиной и уже собранные строки,
      HTTP-статус не 500.
- [ ] Ранее выгруженные каналы перечислены на главной с названием, числом Video
      и Shorts и датой последней выгрузки.
- [ ] Выбор канала из истории показывает его таблицу без единого обращения
      к YouTube API.
- [ ] В таблице, открытой из истории, видно, когда данные были собраны.
- [ ] Удаление записи из истории убирает её видео и снимок, остальные каналы
      не затрагивает.
- [ ] Каждая успешная выгрузка сохраняет снимок `.xlsx` в `history/`, имя файла
      содержит идентификатор канала.
- [ ] Удаление папки `history/` не ломает сервис: список и таблицы читаются из SQLite.
- [ ] `YOUTUBE_API_KEY` отсутствует в клиентском бандле прод-сборки.
- [ ] `README.md` позволяет развернуть и запустить проект с нуля, не заглядывая
      в исходники.
- [ ] `npm run verify` зелёный.

## Открытые вопросы

1. Хранить ли в истории несколько снимков одного канала за разные даты, чтобы
   видеть динамику, или всегда только последний? Сейчас в скоупе — только последний,
   ряд наблюдений во времени явно вынесен в «Не в скоупе».
2. Нужен ли предел на размер архива `history/` — например, хранить последние
   N снимков канала и удалять старые?

Решено 2026-09-21 (ранее было открытым вопросом): **отдельной кнопки «Обновить»
не будет**. «Начать» всегда обращается к YouTube и обновляет данные; чтение без
обращения к API — это выбор канала из истории. Устаревание кэша по времени не
вводится: пользователь сам решает, когда обновить.
