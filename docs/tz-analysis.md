# Анализ ТЗ

**Источник:** `tz.txt`
**Дата:** 2026-09-21

Разбор требований перед PRD: что в ТЗ однозначно, что требовало решения, где
обнаружены пробелы и риски.

## 1. Что однозначно

Пункты 1, 2, 5, 6, 8, 9 читаются буквально и вопросов не вызывают: без авторизации,
форма из пяти элементов, кнопка выгрузки в Excel, приватный репозиторий, Next.js +
React + ESLint + SQLite, работа через issues.

## 2. Решения, принятые до PRD

### 2.1. Источник данных — YouTube Data API v3

Альтернатива (скрейпинг страниц) отклонена: парсер ломается при каждом редизайне
YouTube, упирается в капчи и блокировки по IP и формально нарушает ToS.

**Расход квоты считается так.** Квота — 10 000 единиц в сутки. Ключевое решение:
не использовать `search.list` (100 единиц за вызов) для перебора видео. Вместо него:

| Вызов                | Что даёт                             | Цена |
| -------------------- | ------------------------------------ | ---- |
| `channels.list`      | id канала и плейлист загрузок `UU…`  | 1    |
| `playlistItems.list` | 50 идентификаторов видео за страницу | 1    |
| `videos.list`        | метрики и длительность для 50 видео  | 1    |

Канал на 1000 видео обходится в 41 единицу. Суточной квоты хватает примерно
на 240 000 видео, поэтому требование «выгрузить все видео» из п.2 ТЗ выполнимо
без оговорок.

Исключение — адрес вида `/c/CustomName`: у API нет способа разрешить его напрямую,
остаётся `search.list` за 100 единиц. Такие адреса редки, но обработать их нужно.

### 2.2. Дизлайки — столбец убран

YouTube убрал публичные дизлайки в декабре 2021. Их не отдаёт ни API, ни страница
видео. Сторонние сервисы (Return YouTube Dislike) дают экстраполяцию по выборке
пользователей расширения, то есть оценку, а не факт.

**Сознательное отступление от п.3 ТЗ:** столбца «ДизЛайки» в таблице нет, в формулу
вирусности дизлайки не входят. Зафиксировано в PRD, при UAT (этап 9 регламента)
расхождением не считается.

### 2.3. Issues заводятся через Personal Access Token

`gh` CLI не установлен; deploy key даёт только git-транспорт, но не доступ к GitHub API.
Токен с правом `Issues: read and write` передаётся через переменную окружения
`GITHUB_TOKEN` и в репозиторий не попадает.

## 3. Пробелы в ТЗ и как они закрыты

### 3.1. Как отличить Shorts от обычного видео

**В ТЗ не описано, а API признака не отдаёт.** Оба типа лежат в одном плейлисте
загрузок и выглядят одинаково.

Признак — длительность: Shorts не длиннее 180 секунд (лимит поднят с 60 до 180
в октябре 2024). Обратное неверно — короткое обычное видео тоже уложится в 180 секунд.

Решение: длительность ≤ 180 с даёт **кандидата** в Shorts; кандидат подтверждается
запросом к `youtube.com/shorts/<id>` — настоящий Short отвечает страницей, обычное
видео уходит в редирект на `/watch`. Проверка не тратит квоту API, но добавляет
по HTTP-запросу на каждого кандидата, поэтому выполняется пакетно и только для них.

**Это главный технический риск проекта** — эвристика держится на поведении, которое
YouTube не обещает. Поэтому задача уходит в первую фазу плана.

### 3.2. Что означает «количество видео», когда выбран один тип

**В ТЗ неоднозначно.** «50 видео» при снятой галочке Video — это 50 последних
загрузок, среди которых окажется сколько-то Shorts, или именно 50 Shorts?

Решение: число означает количество строк **выбранных типов** в итоговой таблице.
Выгрузка идёт страницами, пока не наберётся запрошенное количество подходящих
либо не кончится канал. Это отвечает смыслу «проанализировать 50 Shorts».

### 3.3. Формула вирусности

**ТЗ задаёт входы, но не формулу.** Входы после отказа от дизлайков: просмотры,
лайки, комментарии.

Абсолютная вовлечённость несравнима между каналами и между типами: у Shorts она
структурно другая, чем у длинных видео. Поэтому оценка делается **относительно
медианы по выгрузке, отдельно для Video и отдельно для Shorts**:

```
ER          = (лайки + 2 × комментарии) / просмотры
Вирусность  = round(10 × (0,6 × ER / ER_медиана + 0,4 × просмотры / просмотры_медиана), 1)
```

Читается так: **10,0 — типичное видео своего типа на этом канале**, больше — выше
среднего. Верхняя граница 100. Комментарий весит вдвое против лайка: он требует
заметно большего усилия.

Следствие, важное для реализации: вирусность зависит от всей выгрузки, а не от
отдельной строки, и потому считается один раз по завершении выгрузки, а не при
отрисовке страницы таблицы.

### 3.4. Видео со скрытой статистикой

**В ТЗ не упомянуто.** Автор может отключить лайки или комментарии — API тогда
не возвращает поле вовсе. Это `null`, а не ноль, и путать их нельзя: ноль лайков
и скрытые лайки — разные факты.

Решение: в таблице «н/д», в расчёт медианы такие видео не входят, вирусность
у них «н/д». При `просмотры = 0` вирусность тоже «н/д» — делить не на что.

### 3.5. Долгая выгрузка

**В ТЗ не упомянуто.** Канал на 5000 видео — это около 200 HTTP-запросов и минуты
ожидания. Молча висящая кнопка «Начать» на таком сроке неприемлема, а обычный
запрос может не дожить до конца.

Решение: выгрузка оформляется заданием со статусом в SQLite, интерфейс показывает
прогресс («получено 350 из ~5000»). Это же даёт осмысленное поведение при
исчерпанной квоте и при обрыве связи.

### 3.6. Роль SQLite

**В ТЗ названа технология, но не её назначение.** База используется для двух вещей:
кэш выгрузок (повторный запрос того же канала не тратит квоту) и источник строк
для таблицы — сортировка и пагинация идут запросом к БД, а не по массиву в браузере.
На выгрузке в десятки тысяч строк это разница между отзывчивой таблицей и зависшей.

Отсюда же берётся кнопка «Обновить» — иначе закэшированные метрики устареют,
а способа их перезапросить не будет.

## 4. Риски

| Риск                           | Последствие                      | Что делаем                                                    |
| ------------------------------ | -------------------------------- | ------------------------------------------------------------- |
| Эвристика Shorts ломается      | Неверный тип в таблице           | В первую фазу; проверка подтверждением через `/shorts/<id>`   |
| Квота исчерпана                | Выгрузка обрывается              | Понятное сообщение и частичный результат, а не ошибка 500     |
| `/c/CustomName` не разрешается | Канал не найден                  | Фоллбэк на `search.list`, предупреждение о цене в квоте       |
| Канал на десятки тысяч видео   | Долгая выгрузка, тяжёлая таблица | Задание с прогрессом, пагинация на стороне БД                 |
| Ключ API утёк в бандл          | Чужой расход квоты               | Переменная без `NEXT_PUBLIC_`, проверка на этапе 7 регламента |
