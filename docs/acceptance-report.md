## Lighthouse

Прод-сборка, headless Chrome, две одинаковые прогонки подряд.

| Категория      | Оценка |
| -------------- | ------ |
| Performance    | 84–85  |
| Accessibility  | 100    |
| Best Practices | 100    |
| SEO            | 100    |

Метрики: FCP 1,0 с · LCP 4,1 с · TBT ~180 мс · CLS 0 · Speed Index 2,1 с.

**Почему Performance не 100.** Всё упирается в LCP: из 4,1 секунды около 88 % —
render delay, то есть время до того, как React оживит страницу. Сама разметка
приезжает быстро (FCP 1,0 с), CLS нулевой, ответ сервера — 40 мс. Lighthouse
при этом душит процессор вчетверо, а страница объявлена `force-dynamic`: она
обязана собираться на каждый запрос, потому что показывает живые данные.

Пробовали вынести таблицу и панель сравнения в отдельные чанки через
`next/dynamic` — оценка не изменилась (82 против 84, то есть в пределах шума
между прогонами), а лишний слой появился бы. Откатили: сложность без выгоды.
Неиспользованный JS, на который жалуется Lighthouse, — это код самого Next
и React, а не наш.

**Исправлено по итогам прогона:** контраст расхода квоты в строке состояния
был 4,1 при требуемых 4,5 — подняли непрозрачность, после чего доступность
стала 100.

## Безопасность

| Проверка                           | Результат                                                                     |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| `npm audit`                        | 0 уязвимостей                                                                 |
| Значение ключа в клиентском бандле | Нет. Проверяет `npm run check:key` по `.next/static`                          |
| `X-Content-Type-Options`           | `nosniff`                                                                     |
| `X-Frame-Options`                  | `DENY`                                                                        |
| `Referrer-Policy`                  | `strict-origin-when-cross-origin`                                             |
| `Permissions-Policy`               | камера, микрофон, геолокация и FLoC выключены                                 |
| `Content-Security-Policy`          | `default-src 'self'`, скрипты по одноразовому nonce, `frame-ancestors 'none'` |

Заголовки проверяются по настоящему ответу сервера (`tests/e2e/security.spec.ts`),
а не по содержимому конфига: заголовок, описанный, но не доехавший до браузера,
не защищает ни от чего. Отдельный тест убеждается, что при строгом CSP страница
остаётся живой и в консоли нет ни одной заблокированной загрузки.

## Про дизлайки ещё раз

YouTube убрал публичные дизлайки в декабре 2021: их не отдаёт ни API,
ни страница видео. Сторонние сервисы показывают их до сих пор, но там
экстраполяция по выборке тех, у кого стоит расширение, — оценка вместо факта.
Ставить такую оценку в колонку рядом с настоящими просмотрами значило бы
выдавать догадку за данные, поэтому дизлайки исключены и из таблицы,
и из формулы вирусности. Решение зафиксировано в PRD и на UAT расхождением
не считается.
